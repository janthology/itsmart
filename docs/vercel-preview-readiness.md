## Applied database change — atomic asset creation (`00018`)

Scope: add RLS-protected `asset_tag_counters` and `asset_creation_requests` tables and the `create_asset_with_history` RPC. Active administrator/support calls allocate a Philippine-local yearly tag, create an asset and server-attributed creation history together; identical retry request IDs return the prior result. The request ledger retains the submitted JSON payload (including notes and other potentially sensitive asset information) and actor; the prepared migration revokes direct access from ordinary authenticated and service-role callers, but database owners and other privileged roles remain able to bypass those protections. Its profile foreign key cascades on profile deletion, and asset deletion sets its asset reference to null. This ledger is not the three-year audit stream and has no automatic retention policy. Existing direct writers remain enabled, including their manual-tag race and the ability for staff to forge direct asset-history attribution until the separately reviewed `00015` guard is applied. This migration does **not** deploy the frontend, delete existing records, reset the database, modify Auth, or apply other migrations. `docs/security-remediation-stage-3.md` describes risks, synthetic tests and ordering.

Additional preflight metadata: asset and history tables have RLS enabled but not forced; authenticated has SELECT and INSERT grants subject to the existing policies. Current insert policies permit active staff; current history insert policy does not bind `changed_by` to the caller. `assets.asset_tag` is unique, profiles and assets have primary keys, and the history foreign keys match the assumptions. The RLS-bypassing RPC relies on explicit role checks and triggers rather than caller table policies. The observed `public` default ACLs for `postgres` and `supabase_admin` grant `service_role` full table privileges and function execution; the migration explicitly revokes them for its new objects. That does not constrain database owners or other privileged roles. A full audit of all callers and live concurrent legacy writers is still outstanding. Test real calls only with separately approved synthetic records.
